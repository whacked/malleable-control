# GT Rich-Edit Prototype: Lessons Learned

## Theses validated

The prototype confirms all three theses from the spec:

1. **Inline widget injection works.** `BrTextAdornmentDynamicAttribute` with `beReplace` (checkboxes, buttons) and `beAppend` (color swatches) renders live `BlElement` widgets inline in the text flow of a `BrEditor`.
2. **Syntax delimiter hiding works.** `BrTextHideAttribute` collapses `**` markers to zero width while `BlFontWeightAttribute` bolds the inner text. The source rope is never modified.
3. **Cursor-driven restyling works.** Registering `BrTextEditorCursorMovedEvent` on the editor model and calling `styleText` re-runs the styler. Checking cursor position against token ranges toggles between raw source and rendered widgets.

## GT/Bloc pitfalls discovered

### BrEditor ignores text-level attributes for base styling

Setting `foreground:` or `fontSize:` on the roped text before passing it to `BrEditor` has **no visible effect**. The editor's aptitude controls base text appearance. You must use:

```smalltalk
editor aptitude: (BrGlamorousRegularEditorAptitude new
    foreground: aColor;
    fontSize: aNumber;
    background: aColor).
```

Text attributes applied inside the **styler** (e.g. `BlTextForegroundAttribute` on specific ranges) DO work and override the aptitude for those ranges.

### BrCheckbox needs BrGlamorousCheckboxAptitude

`BrCheckbox new` renders as an invisible square without an aptitude. You must add:

```smalltalk
cb aptitude: BrGlamorousCheckboxAptitude new.
cb beNormalSize.
```

Same pattern as `BrButton` needing `BrGlamorousButtonWithLabelAptitude`.

### BlAbsoluteLayout does not exist — use BlBasicLayout

GT v1.1.564 has `BlBasicLayout` for position-based (absolute) layout. `BlAbsoluteLayout` was the name in an earlier Bloc version and produces "undeclared variable" errors.

### Chunk format: bare ! in method bodies breaks fileIn

In `.st` chunk files, `!` is the method/category delimiter. A `!` inside a string literal (e.g. `'Hello!'`) is interpreted as a chunk boundary, producing "Unmatched ' in string literal" errors. Either double it (`!!`) or avoid `!` in strings.

### BrLabel computes 0 intrinsic height in linear layouts

`BrLabel` with `fitContent` vertical constraint can report 0 height, making it invisible in a `BlLinearLayout vertical`. Workaround: use `BlTextElement` with `c vertical exact: 20` (explicit height).

### matchParent in BlLinearLayout consumes all space

In a `BlLinearLayout vertical`, a child with `c vertical matchParent` takes all remaining parent space, correctly leaving room for `fitContent` siblings. But only if the siblings actually compute nonzero intrinsic size (see BrLabel issue above).

### BlPluggableStyler block receives the text — cursor state is external

The styler block receives `aText` (the rope to decorate). Cursor position must be queried from the `BrTextEditorModel` captured in the closure. Use `editorModel useSyncStylerStrategy` to ensure cursor state is current when the styler runs.

## Button handler model

Buttons use `<<label>>` syntax (Hyperbole-style). A handler table (`Dictionary`) maps label strings to blocks. The stencil block in the styler looks up the handler **fresh on every restyle**, so toggling between raw text and rendered widget never loses the handler association. This avoids the DOM-style "detached event handler" problem entirely — the rope text is the single source of truth, and the handler binding is by name, not by reference.

## Architecture summary

```
Source rope (BlRunRopedText)
  never modified by styling — only attributes added/removed
    │
    ▼
BlPluggableStyler (privateStyle: aText)
  scans text with regex → token ranges
  checks cursor proximity per token
    │
    ├── cursor near:  BlTextForegroundAttribute (highlight raw syntax)
    └── cursor away:  BrTextHideAttribute + BrTextAdornmentDynamicAttribute
                        (hide delimiters, inject widgets)
    │
    ▼
BrEditor + BrGlamorousRegularEditorAptitude
  renders the attributed rope as a single Bloc scene graph
  aptitude controls base text color/size/background
    │
    ▼
BrTextEditorCursorMovedEvent → styleText (restyle loop)
```
